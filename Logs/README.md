# 开发日志 · 索引

> 记录「做过什么、为什么、接下来做什么」。设计文档在 `../Docs/`，两者职责分开：
> **Docs = 要做成什么；Logs = 做过什么。**

## 分类

| 目录 | 用途 | 命名 |
|---|---|---|
| `01-开发日志/` | 每次工作的过程、发现、判断、下一步 | `YYYY-MM-DD.md`，同日多篇加 `-2` |
| `02-决策记录/` | 需要长期遵守的选择（含被否决的方案） | `DEC-0001-标题.md` |
| `03-技术验证/` | 技术可行性试验与结论 | `SPIKE-0001-标题.md` |
| `04-问题记录/` | P0/P1 缺陷、根因、修复 | `BUG-0001-标题.md` |
| `05-里程碑/` | 阶段目标、验收清单、复盘 | `M0-立项.md` … `M5-发布.md` |

## 书写约定

- 时间用 Asia/Shanghai，写绝对日期，不用「今天/昨天」。
- 只写事实、判断、下一步；不贴大段代码（代码在工程里，结论写这里）。
- 路径从 `AB/` 根写起：`GameSS/Assets/...`、`Docs/...`。
- 每次会话结束前更新当天日志，并同步本索引。
- 决策一旦「已定」不删改，推翻时新建一篇并标注「取代 DEC-XXXX」。
