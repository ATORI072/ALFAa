# DEC-0001 日志与文档目录规范

- 状态：已定
- 日期：2026-11-15
- 决策人：用户（提出要求）+ AI（落地方案）

## 背景

用户要求 AI 的开发日志从游戏工程里单独拎出来、按类别存放；同时授权后续直接修改 Unity 工程文件。

## 选项

- **A. 放 `GameSS/Logs/`**：位于 Unity 工程内，随手可见，但会与 Unity 自身日志混在一起，且可能被版本控制/清理流程误伤。
- **B. 放 `AB/Logs/`**：位于 Unity 工程之外、AB 根目录下，与 `Docs/` 并列。
- **C. 并入 `AB/Docs/`**：少一个顶层目录，但文档与流水日记混杂，检索成本高。

## 决定

选 **B**：`AB/Logs/`，下设 `01-开发日志`、`02-决策记录`、`03-技术验证`、`04-问题记录`、`05-里程碑`。

## 理由

- 在 `Assets` 之外，Unity 不会导入、不会生成 `.meta`、不参与构建，也不会触发重导入。
- 与 Unity 自己的 `GameSS/Logs/` 明确区分，避免「日志」一词歧义。
- 与 `Docs/` 职责分离：Docs 描述目标设计，Logs 记录执行过程与依据。
- 仍位于 AB 目录内，备份/迁移时可一起带走。

## 影响

- 后续每次会话在 `Logs/01-开发日志/` 留一篇；关键选择、技术验证、P0/P1 缺陷分别独立编号成篇。
- 日志为纯文本、体积小，将来若迁移到 Git 可一并入库。
- 索引维护在 `Logs/README.md`。
