## 1. 产品定义

### 1.1 设计支柱（Pillars）

一切设计决策以此为准，冲突时按序号取舍。

1. **射击即解谜（Shooting is the puzzle verb）**
   枪不只是武器，也是钥匙。开关、镜面、锁链、敌人护盾、空间结构，都用「打哪里、什么时候打、用什么弹」来解。战斗房间本身就是谜题房间。
2. **少女与枪的反差美学**
   柔和的动漫角色演出 × 冷硬的枪械与破坏；安静的解谜时刻与爆发式的战斗交替，形成节奏反差。
3. **可读的立体空间**
   第三人称视野内的机关必须「一眼看懂用途」，用颜色、光、动效做视觉语言，不靠文字提示。

### 1.2 体验目标（玩家离开 demo 时应说出的话）

- 「打枪很跟手，打中很有感觉。」
- 「原来这个机关是让我射的。」
- 「这个女孩子挺可爱，我想知道她接下来去哪。」

### 1.3 明确不做（Non-goals，防范围膨胀）

- ❌ 开放世界 / 大地图自由探索
- ❌ 联机、PVP、排行榜
- ❌ 多角色养成、抽卡、装备词条
- ❌ 全流程语音（仅关键演出有语音）
- ❌ 移动端适配（切片阶段不做，架构预留）
- ❌ 复杂潜行系统、载具、合作 AI 指令轮盘

### 1.4 内容量目标

| 内容 | 垂直切片（M2） | 完整版（M3） |
|---|---|---|
| 关卡/章节 | 1 关（15–20 min） | 3 章（60–90 min） |
| 敌人类型 | 2（近战 + 远程） | 4 + 1 Boss/章 |
| 武器 | 2（手枪 + 步枪） | 3（+ 电磁/霰弹） |
| 谜题 | 3 个 | 8 个 |
| 可交互道具 | 6 种 | 12 种 |
| 过场演出 | 1 段（30 s） | 6 段 |
| 角色 | 主角 1（1 套服装） | 主角 1（2 套）+ NPC 2 |
| 流程时长 | 15–20 min | 60–90 min |

## 2. 玩法框架

### 2.1 核心循环（Core Loop）

```
探索区域 → 侦察（发现机关/敌人/路线）
   ↑                 ↓
奖励/剧情 ← 解锁通道 ← 战斗 + 射击解谜（交替进行）
```

单房间微循环（30–90 秒）：
**观察 3 秒 → 决策 5 秒 → 执行（射击/走位）20 秒 → 反馈（开门/掉落/演出）5 秒**

### 2.2 射击与解谜的耦合规则（设计约束）

每个谜题至少满足以下两条中的一条，否则不做：

- **A. 必须开枪**：目标只能被子弹命中/击碎/推动。
- **B. 在火力压力下解**：解谜过程中有敌人或倒计时，迫使玩家边打边想。

谜题类型池（按实现成本排序）：

| 类型 | 机制 | 成本 | 用在 |
|---|---|---|---|
| 射击开关 | 打中指定靶点 → 信号 | 低 | 教学、门锁 |
| 顺序锁 | 按顺序/节奏打多个靶 | 低 | 第 1 章 |
| 镜面反射 | 子弹反弹命中死角靶 | 中 | 第 2 章 |
| 元素弹 | 电磁弹激活机关、普通弹破坏 | 中 | 第 2 章起 |
| 重量/物理 | 射落吊物压住踏板 | 中 | 第 3 章 |
| 空间透视 | 利用第三人称视角看穿/对齐 | 高 | 第 3 章高潮 |

### 2.3 战斗设计

- **越肩视角**，默认右肩，可切换；腰射 + 瞄准（ADS）。
- **移动**：走/跑/闪避（i-frame 0.2 s）/掩体探头（P1，可砍）。
- **武器**：手枪（精准、爆头收益高）、步枪（连射、压制）；第三把电磁枪兼作解谜工具（P1）。
- **敌人三档**：
  - 冲锋兵：直线逼近、近战挥击，逼玩家走位；
  - 射手：找掩体、点射，逼玩家换位；
  - 机关兵（P1）：连接谜题，击杀后机关解锁——把战斗与解谜绑在一起。
- **反馈优先级**（手感三件套，M1 必须做完）：命中停顿（hitstop）、镜头震动、命中特效/音效。

### 2.4 关卡结构（垂直切片）

```
教学走廊（移动/视角）
  → 战斗房 A（2 冲锋兵，教射击）
  → 解谜房 B（顺序靶 ×3，教「射击=开关」）
  → 战斗房 C（射手 + 移动掩体，边打边解）
  → 电梯/过场（30 s）
  → 高潮房 D（小 Boss：护盾需打弱点，弱点由机关暴露）
```

设计规则：**每个新机制先在安全房教学，再在压力房考核，最后组合使用（教 → 考 → 合）。**

## 3. 技术方案

### 3.1 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 引擎 | Unity 2022.3.62f3c1 LTS | 本机已装；LTS 稳定；URP 生态成熟 |
| 渲染 | URP 14.x + 自定义 Toon/Outline | 动漫风可控、性能好、移动端可延展 |
| 输入 | Input System 1.7（Action Asset） | 键鼠/手柄双方案、可重绑定 |
| 相机 | Cinemachine 2.9（3rd Person Follow + Aim） | 越肩/瞄准过渡、Impulse 震屏开箱即用 |
| 角色控制 | CharacterController + 自研 Motor | 坡道/台阶稳定，逻辑简单可控 |
| UI | UGUI + TextMeshPro | 迭代快、美术友好（UI Toolkit 备用） |
| 动画 | Animator 分层 + Timeline + Playable | 状态机分层复用；Timeline 做演出 |
| 布料/头发 | Magica Cloth 2（或 Dynamic Bone） | 裙摆/头发物理，动漫风必需 |
| 资源管理 | Addressables | 分场景/分章加载，后期可换 YooAsset |
| 音频 | Unity Audio Mixer（后期可换 FMOD） | 先满足需求，避免早期引入中间件 |
| 存档 | JSON + 版本号，Application.persistentDataPath | 简单可调试 |
| 本地化 | Unity Localization（CSV） | 中/英双语 |
| 测试 | Unity Test Framework（EditMode + PlayMode） | 纯逻辑单测 + 关键流程冒烟 |
| 版本控制 | Git + Git LFS | 二进制资产管理；分支策略见 §6 |

> 版本锁定原则：所有包版本写入 `Packages/manifest.json` 并在 M0 冻结；不引入依赖旧 Built-in 管线的商店资源。
>
> **版本控制现状（2026-11-15）**：`GameSS` 由 Unity 创建时接入了 UVCS/Plastic workspace（`.plastic/`、`ignore.conf`），尚未初始化 Git。若沿用 UVCS，§6.1 的 Git 流程需换成 UVCS 的分支/changeset 流程；若改 Git + LFS，需重新初始化。此项待拍板。

### 3.4 关键系统设计要点

**交互系统**
```csharp
public interface IInteractable {
    string Prompt { get; }          // "按 E 拉下闸门"
    bool CanInteract(GameObject actor);
    void Interact(GameObject actor);
}
```
- `InteractionScanner`：从相机中心 SphereCast 3 m，每帧取最近可交互物，驱动 HUD 提示。
- 支持「点按」与「长按」（0.6 s 环形进度）。

**信号系统（解耦谜题）**
- `SignalChannel : ScriptableObject`（bool/int 两种），发射/监听均走资产引用。
- 好处：机关与门、灯、音效零代码耦合，关卡策划可在 Inspector 连线。

**谜题控制器**
- 状态机：`Idle → Armed → Solved / Failed`；支持 AND / OR / Sequence / Timer 组合。
- `PuzzleDefinition`（SO）描述：触发条件、输入信号、输出信号、重置策略、提示文本。
- 统一 `Reset()`，支持死亡后自动复位（避免软锁）。

**射击**
- 主武器 hitscan：`Physics.Raycast` + 分层 LayerMask（Hitbox / Environment / PuzzleTarget）。
- 弹道表现：Tracer 拖尾 + 枪口火光 + 弹壳 + 命中贴花（对象池）。
- 伤害：`DamageInfo { amount, type, hitPoint, normal, isHeadshot, source }`。
- 辅助瞄准：手柄用球形吸附（角速度限制），键鼠不加磁吸，仅准星扩散反馈。

**AI**
- 轻量 FSM（不用 Behavior Tree，省实现成本）：Patrol / Investigate / Chase / Attack / Stagger / Dead。
- 感知：视锥 90°、12 m + 射线遮挡 + 听觉半径（枪声 20 m）。
- NavMeshAgent 驱动，攻击点用「掩体点 + 侧翼点」标注。

**存档**
- 检查点式：`SaveData { version, checkpointId, hp, ammo, weapons, puzzleStates, collectibles, playTime }`。
- 谜题状态按 `puzzleId` 持久化，读档后机关恢复正确状态。

### 3.5 性能预算（1080p / 60 fps，GTX 1660 级）

| 指标 | 预算 |
|---|---|
| 主线程 CPU | ≤ 8 ms |
| Draw Call | ≤ 1200 |

## 4. 美术与内容管线

### 4.1 动漫美少女角色管线

```
VRoid / Blender 建模 → VRM 导出 → Unity（UniVRM 导入，Humanoid Avatar）
  → Toon 材质（lilToon / 自研 URP Toon）+ 描边
  → BlendShape 表情（8 种）+ 口型（5 个元音）
  → 骨骼 / 头发 / 裙摆物理（Magica Cloth 2）
  → 动画（Mixamo 重定向 / VRMA / 手 K）→ Animator 分层
```

角色规格（切片）：

| 项 | 目标 |
|---|---|
| 面数 | 4–6 万三角面（含头发） |
| 材质数 | 4–6（皮肤/脸/头发/服装/武器） |
| 贴图 | 2K × 6，BC7 压缩 |
| 表情 | 8（喜/怒/哀/惊/羞/思考/战斗/失神） |
| 动画 | 约 25 条（见 §4.3） |
| 描边 | 反转壳，宽度 0.02–0.03，法线平滑 |

> 关键决策：**先灰盒 + 占位 VRM，M2 前不追最终美术**。角色最终模型是最大外部依赖，必须在 M1 结束前定好供应商/方案。

### 4.2 场景与光照

- 模块化套件（墙/地/门/柱/管线），单模块 2–4 m，网格吸附 0.25 m。
- 光照：Baked GI（Lightmap）+ 1 实时主光；关键演出用局部 Volume 调色。
- 风格化：卡通描边 + 高饱和色块 + 少量 Bloom/DOF；避免 PBR 写实材质。
- 视觉语言：可交互物统一「青色发光边缘 + 轻微呼吸动画」；危险物「红色脉冲」。

### 4.3 动画清单（切片）

| 类别 | 数量 | 来源 |
|---|---|---|
| 移动（8 向 idle/walk/run） | 8 | Mixamo 重定向 / VRMA |
| 瞄准（idle/walk） | 2 | 手 K 上半身层 |
| 射击（腰射/ADS/换弹） | 3 | 手 K |
| 受击/死亡 | 4 | Mixamo |
| 闪避 | 2 | 手 K |
| 交互（拉杆/拾取/开门/按键） | 4 | 手 K |
| 演出 | 2 | Timeline |
| 合计 | ~25 | — |

Animator 分层：Base（移动）+ UpperBody（瞄准/射击，Avatar Mask）+ FullBody（交互/受击，Override）。

### 4.4 音频

- 三层混音：Master → BGM / SFX / Voice / UI。
- 枪声「近/远」双层 + 尾音混响区（Reverb Zone）。
- 交互音必须与视觉同步（±1 帧），谜题成功给「上行三音」奖励音。
- 切片音频量：BGM 2 首（探索/战斗）、SFX 约 60 个、VO 关键台词 10 句（可选）。

### 4.5 内容生产规范

- 所有可调数值外置为 SO / CSV，**不写死在代码里**。
- 命名：`PF_`、`MAT_`、`ANIM_`、`SO_`、`SFX_`、`BGM_` 前缀 + 模块名。
- 每个 Prefab 必须有 `README` 备注（用途/依赖/负责人）——用 Prefab 上的 `Note` 组件承载。

## 6. 工程与协作规范

### 6.1 版本控制

- Git + Git LFS（`*.fbx *.png *.psd *.wav *.mp3 *.vrm *.exr`）。
- 分支：`main`（可发布）← `dev`（集成分支）← `feat/xxx`、`fix/xxx`。
- 提交信息：`feat(combat): 加入命中停顿` / `fix(puzzle): 修复读档后开关不复位`。
- 每周五打 tag `w##`，出 build 归档。
- 场景/预制体冲突高发：**约定同一时间只有一人改同一场景**，用 `Level01_Art` / `Level01_Logic` 拆分降低冲突。

### 6.2 代码规范

- 命名空间 `AB.<Module>`；文件与类同名；一个文件一个 public 类。
- 禁止 `Find`/`SendMessage`/`Resources.Load` 散落调用；统一走服务/Addressables。
- 事件用 `SignalChannel` 或 C# event，禁止跨模块硬引用。
- 所有 `Update` 中的分配为 0（避免 GC）；对象池覆盖子弹/特效/伤害数字。
- 代码评审：单人开发也要「隔天自审 + 静态检查」，关键系统写单测。

## 7. 质量保障

- **每周可玩 build**：周五打包，自己完整通一遍（不许用编辑器作弊）。
- **试玩节奏**：M1 末 3 人、M2 末 8–10 人、M3 每月 5 人；只观察不提示，记录卡点时间。
- **Bug 分级**：
  - P0 阻断/崩溃/存档损坏 → 当天修；
  - P1 严重体验问题 → 本周修；
  - P2 一般 → 排期；
  - P3 打磨 → 有空再做。
- **自动化**：谜题状态机、伤害公式、存档序列化写 EditMode 单测；玩家移动/射击做 PlayMode 冒烟。
- **性能门禁**：Draw Call / 帧时间超预算即阻断合入（先人工检查，后期接 CI）。

## 附录 B：术语

- **DoD**：Definition of Done，完成的验收标准。
