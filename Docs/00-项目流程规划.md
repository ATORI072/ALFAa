## 1. 范围重定：从「游戏」缩到「一个盒子」

### 1.1 为什么必须缩

v0.1 假设「1 程序 + 1 兼职美术」，现在实际是「1 个零经验学生」。经验、素材、资金三项都为零时，**内容量是唯一能自由控制的变量**。缩范围不是降低标准，是把有限的完成度集中在一个点上。

砍法：

- 3 章 → **1 个箱庭**
- 4 敌人 + Boss → **2 敌人 + 1 小 Boss**
- 3 武器 → **2 武器**（手枪 + 步枪，第三把留到下次）
- 8 谜题 → **3 谜题**
- 60–90 分钟 → **10–15 分钟**
- 中英双语 → **先中文**，架构留本地化接口

### 1.2 切片内容清单（做完即发布）

| 类别 | 内容 | 备注 |
|---|---|---|
| 空间 | 1 个箱庭：校舍 1F/2F/3F 天台 + B1 | 30×30 m，三层垂直 |
| 主角 | 1 名动漫少女（VRoid 自制） | 1 套服装，8 表情 |
| 武器 | 手枪（精准）、步枪（连射） | 共用一套命中反馈 |
| 敌人 | 冲锋兵、射手 | 各 1 种行为 |
| Boss | 「钟塔守卫」1 个 | 2 阶段，弱点射击 |
| 谜题 | 配电顺序、镜面反射、Boss 弱点 | 各教一个机制 |
| 演出 | 开场 20 s + 结尾 20 s | Timeline 或直接运镜 |
| UI | HUD、暂停、设置、结算 | 中文 |
| 音频 | 2 首 BGM + 约 40 个音效 + 关键台词 | VOICEVOX 可选 |
| 时长 | 10–15 分钟 | 含死亡重试 |

### 1.3 明确不做

开放世界、联机、多角色养成、抽卡、全语音、移动端、潜行系统、载具、合作 AI、成就系统、多结局、Steam 上架（先 itch.io）。

### 1.4 完成度标准（Definition of Done）

- 从主菜单到通关无阻断、无报错；
- 1080p / 60 fps（你的 5060 绰绰有余，按集显 60 fps 做更稳）；
- 3 名同学能不看攻略通关；
- 有一个 60 秒的展示视频；
- 工程有 README、CREDITS、可复现的启动步骤。

## 2. 玩法：箱庭 × 射击解谜

### 2.1 什么是箱庭

箱庭（Hakoniwa）原意是「 miniature garden 」，在游戏里指**边界明确、密度极高、可反复穿行的小型立体空间**。它不是「小地图」，而是：

- **边界清楚**：玩家一眼能感知「这个盒子有多大」；
- **密度高**：单位面积里的决策点多（可打的东西、可走的路、可解的锁）；
- **立体**：高低差带来视野、路线、战术变化；
- **可回访**：拿到新能力/新知识后，同一个空间产生新走法。

> 一句话：**箱庭的乐趣不是「大」，是「每一平米都有用」。**

参考：《超级马力欧 奥德赛》的各国、《杀手》的关卡、《耻辱》的关卡、《生化危机 2》的警局、《塞尔达》的神庙。

### 2.2 箱庭设计四问（每次改关卡都问一遍）

1. **第一眼看到什么？**（地标：钟塔 / 天窗 / 巨大的破损黑板）
2. **玩家先去哪？**（动线：光、声音、敌人、可交互高亮）
3. **为什么回来？**（回访：拿到新钥匙/新弹种后解锁的旧区域）
4. **哪一次交互改变了整个空间？**（系统性：一枪打灭总闸，全楼灯灭、敌人视野变化、电梯停运）

第 4 问是「射击 × 箱庭」的题眼：**让一发子弹同时影响战斗、解谜、路线三件事。**

### 2.3 首个箱庭方案：《黄昏校舍》

**主题**：黄昏的废弃校舍，异界侵蚀从钟塔开始。暖色夕阳 + 冷色异界光，天然适合卡通渲染，也省灯光成本。

**垂直结构**

| 层 | 区域 | 作用 |
|---|---|---|
| 3F | 天台 + 钟塔 | 地标 / Boss 场 / 终局 |
| 2F | 教室 ×2、音乐室、档案室 | 探索 / 镜面谜题 / 钥匙 |
| 1F | 玄关（出生）、中庭、食堂、配电室 | 教学 / hub / 首个谜题 |
| B1 | 锅炉房、仓库 | 电源 / 氛围 / 回访 |

**锁钥网（4 把锁，一条主链 + 两条捷径）**

| 锁 | 钥匙 | 获得方式 | 打开什么 |
|---|---|---|---|
| 电梯断电 | 3 个保险丝 | 配电室顺序射击 | 通往 2F/3F |
| 音乐室门 | 音乐室钥匙 | 2F 射手掉落 | 镜面谜题 |
| 天台门 | 门禁卡 | 音乐室谜题奖励 | Boss 战 |
| Boss 护盾 | 4 个探照灯 | 射击灯罩弱点 | 破防窗口 |

**动线**

```
B1 锅炉房 ←→ 1F 玄关 ── 中庭 ── 食堂
                 │           │
                 │        配电室（谜题 1）
                 │
            中央楼梯 ── 2F 走廊 ── 教室 201/202
                 │           │
                 │        音乐室（谜题 2）
                 │           │
                 └──── 3F 天台（Boss）── 钟塔
```

- **捷径 1**：2F 消防梯直通 1F 中庭（打完 2F 打开，减少回头路）。
- **捷径 2**：B1 锅炉房打通后，电梯恢复，形成「B1—1F—2F—3F」的纵向环路。

**为什么这个盒子适合零预算**

- 校舍是「方盒子 + 重复模块」，用 Kenney 的墙/门/桌椅套件就能搭；
- 室内为主，灯光和雾能遮住资产精度；
- 黄昏 + 异界光 = 强风格，弱化贴图质量；
- 垂直三层，30×30 m 就能做出 10 分钟内容，不用做大世界。

### 2.4 核心循环

```
进入区域 → 观察（地标/敌人/机关）→ 选择（打谁/打哪/走哪）
   ↑                                      ↓
奖励/捷径 ← 解锁（门/电梯/新路线）← 战斗 + 射击解谜
```

单房间 30–60 秒：**看 3 秒 → 想 5 秒 → 打 20 秒 → 反馈 5 秒**。

### 2.5 射击即解谜（硬约束）

每个谜题至少满足一条，否则砍掉：

- **A. 必须开枪**：目标只能被子弹命中/击碎/推动；
- **B. 在压力下解**：解谜时有敌人或倒计时。

三个谜题的分工：

| 谜题 | 教什么 | 考什么 | 用在哪 |
|---|---|---|---|
| 配电顺序 | 射击=开关、顺序 | 三个保险丝按亮度顺序打 | 1F 配电室 |
| 镜面反射 | 子弹会反弹、角度 | 打吊灯链让光折射到光敏开关 | 2F 音乐室 |
| Boss 弱点 | 打弱点=破防 | 边躲弹幕边打 4 个探照灯 | 3F 天台 |

**教 → 考 → 合**：先在安全房单独教，再在有小怪的房间考，最后在 Boss 战组合。

### 2.6 难度与死亡

- 检查点：每层入口 1 个，死亡回检查点，敌人重置、谜题状态保留。
- 无手动存档（切片阶段），退出即重来。
- 死亡惩罚 ≤ 20 秒，保证试玩节奏。

## 3. 技术方案（零预算版）

### 3.1 技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 引擎 | Unity 2022.3.62f3c1 LTS | 已装；用 Unity Student 免费授权 |
| 渲染 | URP 14 + lilToon / Unity Toon Shader | 卡通描边 |
| 输入 | Input System 1.7 | 键鼠 + 手柄 |
| 相机 | Cinemachine 2.9 | 越肩 + 震屏 |
| 角色 | CharacterController + 自研 Motor | 不买任何控制器插件 |
| UI | UGUI + TextMeshPro | 上手快 |
| 动画 | Animator 分层 + Timeline | Mixamo/VRMA 重定向 |
| 头发/裙摆 | VRM SpringBone（UniVRM 自带） | **不买 Magica Cloth** |
| 资源 | Addressables（可后置） | 切片阶段直接引用即可 |
| 音频 | Unity Audio Mixer | 够用 |
| 存档 | JSON + PlayerPrefs | 检查点式 |
| 测试 | Unity Test Framework | 只测谜题状态机与伤害公式 |
| 版本控制 | **Git + GitHub**（学生包免费私有仓库） | 见 §7 |

> 所有插件都用免费版；付费插件（Magica Cloth、Odin、DOTween Pro 等）一律不引入，用自带能力替代。

### 3.2 目录结构

### 3.3 程序集（先简后繁）

第一周只建 `AB.Core` 和 `AB.Gameplay` 两个 asmdef，等模块稳定再拆。**先跑起来，别过早架构。**

### 3.4 关键系统（按实现顺序）

1. **移动 + 相机**：CharacterController、重力、斜坡、冲刺、Cinemachine 越肩。
2. **射击**：hitscan、弹药、换弹、准星扩散、后坐力。
3. **反馈三件套**：hitstop（0.04–0.08 s）、镜头震动、命中特效/音效。
4. **交互**：`IInteractable` + 相机 SphereCast 3 m + 提示 UI。
5. **信号**：`SignalChannel`（ScriptableObject），机关与门零耦合。
6. **谜题**：状态机 `Idle→Armed→Solved/Failed`，支持 AND/OR/Sequence，统一 Reset。
7. **敌人**：FSM（巡逻/调查/追击/攻击/硬直/死亡）+ NavMesh。
8. **存档**：检查点 + 谜题状态 + 武器/弹药。
9. **Boss**：两阶段，阶段切换 = 护盾 → 弱点暴露。

### 3.5 性能预算（1080p / 60 fps）

| 指标 | 预算 |
|---|---|
| 主线程 | ≤ 10 ms |
| Draw Call | ≤ 800（低多边形 + 合批） |
| 可见三角面 | ≤ 1.0 M |
| 纹理内存 | ≤ 800 MB |
| 实时光 | 1 主光 + 2 附加光 |
| 同屏敌人 | ≤ 6 |

低多边形方案下这些预算很宽松，重点盯 **Draw Call 和 GC**。

## 4. 美术与资源（零预算）

### 4.1 美术方向：低多边形 + 卡通渲染

**这是零预算下唯一能统一风格的路。** 免费资源以 low-poly 为主，写实资产又贵又难统一；卡通渲染 + 描边 + 强色彩能把 Kenney 的方块和 VRoid 的少女拉到同一个画面里。

- 色板：夕阳橙 + 异界青紫 + 高饱和点缀；
- 材质：无贴图/纯色 + 少量手绘贴图；
- 光照：烘焙 + 一盏实时主光 + 体积雾；
- 后处理：Bloom（轻）、Color Grading、Vignette（轻）。

### 4.2 角色管线（VRoid → Unity）

```
VRoid Studio 捏人（30–60 分钟）
  → 导出 VRM 1.0
  → UniVRM 导入 Unity（Humanoid Avatar 自动生成）
  → lilToon 材质 + 描边
  → 表情 BlendShape（VRoid 自带 8 种）
  → SpringBone 头发/裙摆
  → Mixamo 动画重定向
```

优点：不花钱、风格统一、可随时改脸和发型。缺点：VRoid 偏「可爱系」，做不了硬核写实——正好符合本项目。

### 4.3 场景

Kenney 模块化套件搭「形」，靠灯光/雾/贴花做「气氛」。资源清单见 [01-零预算资源清单](01-零预算资源清单.md)。

### 4.4 音频

Freesound（CC0）+ Kenney Audio + VOICEVOX（免费日系动漫音）。枪声至少三层：近、远、尾音。

### 4.5 资源红线

- 只收 **CC0 / CC-BY / 明确允许个人使用** 的资源；
- 每个资源在 `Assets/ThirdParty/<来源>/LICENSE.txt` 留许可证；
- 建 `CREDITS.md`，发布时附上；
- 不用「来路不明的网盘整合包」——省下的时间不够排一次雷。

> 你说不涉及商用，但**能公开分享的 demo 才有反馈**，而反馈是独立开发最缺的东西。所以按「可公开」的标准选资源，成本几乎一样。

### 5.3 每周节奏（防拖延）

- **周一 30 分钟**：只定「这周唯一必须完成的一件事」；
- **平日**：每天 1–1.5 h，专注一个任务；
- **周五**：出 build，自己完整玩一遍（不用编辑器作弊）；
- **周末**：2–3 h 补进度 + 1 节策划课；
- **考试周**：只维护，不排新功能。

### 5.4 关键路径

角色（VRoid）→ 动画重定向 → 战斗手感，三者串联。**W7 前必须把角色跑起来**，否则 M2 会挤压试玩时间。

## 6. 学习路径（策划 + 技术）

### 6.1 每日 20 分钟策划课

课程表见 [教学/README](../Docs/教学/README.md)。原则：

- 每课 20 分钟读 + 30 分钟练，练习必须落在当前关卡上；
- 不学「用不上的理论」，学完当周就用；
- 每课留一句「可以立刻改的东西」。

### 6.2 技术学习顺序（只学当前需要的）

1. Unity 基础：GameObject/Component/Prefab/生命周期
2. C# 基础：变量、类、接口、协程、事件
3. 物理与射线：Collider、Raycast、LayerMask
4. 动画：Animator、Avatar、状态机
5. UI：Canvas、布局、事件
6. 性能：Profiler、合批、对象池

> **教程纪律**：卡住时最多看 30 分钟教程；超过就换方案或问 AI。不要连续看 3 小时教程不动手。

### 6.3 学习方法

**拆解 → 模仿 → 改造**：玩 10 分钟参考游戏 → 写下它的一个机制 → 在自己的灰盒里复刻 → 改一个参数看变化。这是进步最快的方式，比看教程快。

## 7. 工程规范（学生版）

### 7.1 版本控制：Git + GitHub（已完成迁移）

工程已迁移至 **Git + GitHub**：

- 远程仓库：`github.com/ATORI072/AB.git`，分支 `main`；
- `.gitignore` 按 Unity 规则排除 `Library/`、`Temp/`、`Logs/` 等；`.gitattributes` 用 LFS 跟踪 fbx/png/wav 等大文件；
- UVCS/Plastic 的 `.plastic/`、`ignore.conf` 仅保留本地，不纳入版本库；
- 以后可接 GitHub Actions 做自动打包（以后再说）。

### 7.2 规范

- 分支：`main`（可玩）+ `dev`（日常）；单人开发不必开 feature 分支。
- 提交：`feat: 加入射击` / `fix: 修复谜题读档不复位`。
- 大文件：切片阶段不用 LFS；若模型/音频超 100 MB 再开。
- 每周五打 tag `w01`…`w16`，对应 build。

### 7.3 备份

代码推 GitHub；工程整包每周压缩一份到移动硬盘/网盘（Unity 工程损坏很常见）。
